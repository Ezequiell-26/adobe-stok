# SKILL — ADOBE METADATA AND SUBMISSION

## Metadata objective

Make every asset discoverable without misleading the buyer or introducing IP risk.

## Title

Create a concise natural-English description of what is visibly present.

Good title structure:

`[primary subject] + [action/state/context]`

Avoid:

- hype;
- unsupported claims;
- emotional claims not evident in the image;
- brand names;
- artist names;
- celebrity names;
- fictional character names;
- government-agency terms used for SEO.

## Keywords

Build the list from the image outward:

1. primary subject;
2. primary action/state;
3. environment/context;
4. important visible attributes;
5. useful commercial concepts that the image genuinely communicates.

Prioritize the strongest concepts first.

Never keyword things that are absent.
Never copy competitors' metadata.
Never keyword-stuff third-party IP.

## Category

Select the category that best matches the actual subject and use case. If ambiguous, use the closest factual category and document the reasoning.

## AI disclosure

For generative content, select the current Adobe generative-AI disclosure during portal submission. Apply fictional people/property disclosure when appropriate under current Adobe rules.

## Pre-submit checklist

- JPEG;
- sRGB;
- 4–100 MP;
- ≤45 MB;
- sharp;
- well exposed;
- no branding/watermark/timestamp;
- metadata truthful;
- releases handled if required;
- AI disclosure correct;
- similarity reviewed;
- generator commercial license verified.

## Submission record

Every asset should have a record based on `templates/SUBMISSION_RECORD.md` containing enough evidence to reproduce the decision.

## Refusal feedback loop

When Adobe refuses an asset, record the exact refusal reason. Update the relevant internal lesson in `memory/` or `skills/` only when the new rule is supported by evidence. Do not generalize from one refusal into a universal Adobe rule without evidence.
